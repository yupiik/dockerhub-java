== Java with Docker CLI

`ossyupiik/java-docker` is a Java 25 JRE with the Docker CLI at `/usr/bin/docker` for applications controlling an external Docker Engine.
It is not a development-toolchain image: it does not provide Maven, gh, a JDK compiler, Docker plugins or a Docker daemon.
The new image uses the official Eclipse Temurin Alpine runtime and copies only the static Docker client from the official Docker CLI image.
Both inputs are pinned by multi-platform index digest in `java-docker/Dockerfile`, independently of the existing Zulu images.
The supported platforms are `linux/amd64` and `linux/arm64` under the same image reference.

The initial release tag is `25.0.5-alpine3.24-docker29.9.2` after the image has been published.
Pin the published index digest in production to preserve platform selection and reproducibility.
Updating either source requires updating its digest, rerunning both platform smoke tests and publishing a matching release tag.

The image defaults to UID/GID `10001:10001`, `HOME=/tmp`, no entrypoint and `java --version` as its command.
It works with a read-only root filesystem and writable `/tmp`, without root initialization or injected credentials.
The upstream system and Java CA stores are retained; custom trust must be provisioned explicitly rather than relying on Temurin's root-oriented certificate entrypoint.
Jib can use this image as its base and generate the application's Java entrypoint without adding a Docker binary during the Maven build.

WARNING: Access to a Docker Engine socket grants host-administration capabilities even when the client runs as non-root.
Provision socket access explicitly on a dedicated trusted host; this image does not start a daemon or grant socket permissions.

Build and test the native platform locally with Docker, Python 3 and JDK 25 installed:

[source,sh]
----
docker build -t java-docker:local java-docker
sh java-docker/test/smoke.sh java-docker:local amd64
SMOKE_HTTPS_URL=https://example.com sh java-docker/test/smoke.sh java-docker:local amd64
----

Use `arm64` instead of `amd64` on an ARM64 host.
The smoke test checks metadata, Java/Docker execution, CA trust, the non-root/read-only contract and the absence of daemon executables without mounting a socket.
The optional HTTPS probe verifies Java TLS trust against a public endpoint; it requires network access.
These checks do not replace testing against the deployment's Docker Engine or a supply-chain/security review.

The dedicated `Java Docker CLI` workflow runs smoke tests on native AMD64 and ARM64 runners for pull requests and changes on `main`.
Publishing is restricted to upstream tags such as `java-docker/25.0.5-alpine3.24-docker29.9.2`, after both platform tests succeed, using the existing Docker Hub secrets.
The Docker Hub `ossyupiik/java-docker` repository and token write permissions must be provisioned before the first release.
No image is published by a pull request, a push to `main` or a manual workflow invocation.
The existing images and their release workflow are unchanged.

A docker image using Yupiik Java docker (v17 as of today) and bootstraping H2 server.
It enables to use it as a remote database quite easily and makes development smoother in several cases - in particular in self-hosted kubernetes environments.

https://hub.docker.com/r/ossyupiik/h2/tags

Example usage:

[source,sh]
----
$ docker run yupiik/h2:2.1.214 -tcp -tcpAllowOthers -tcpPort 9092 -tcpPassword secret -baseDir /opt/storage/h2 [-ifNotExists]
----

Then you can connect to `jdbc:h2:tcp://172.17.0.2:2000/<database>` from any h2 client.
